# Plan: Tianguis Sierra Sur (fases 1 y 2)

Spec: `docs/superpowers/specs/2026-11-19-tianguis-sierra-sur-fases-1-2.md`. Rama `feature/tianguis`; PR sin merge.

## Revisión del repositorio y adaptaciones

| Spec | En el repo | Decisión |
|---|---|---|
| Entidad `Anuncio` | Ya existe `publicidad.Anuncio` (banners) | Paquete `mx.turamohoy.tianguis`: `AnuncioTianguis`, `CategoriaTianguis`, `VendedorTianguis`, `ReporteTianguis`; tablas `tianguis_*`. |
| Fotos como «claves R2» | Productos guardan la **URL pública** y cada subida queda en `foto` (para listar/borrar sin uso) | Igual que el resto: URLs públicas bajo `negocios/tianguis/…`, registradas en `foto`; `Foto.usos()` reconoce anuncios del tianguis. |
| Fotos ~1600 px | Panel: cuadradas 800×800 | Para el tianguis, sin recorte, lado mayor 1600 px, WebP/JPEG (mismo `FotosService`, otra preparación). |
| Tianguis como giro y sección administrable con encargado | Giros con negocios; ENCARGADO ligado a un negocio | Giro `tianguis` + negocio `tianguis` (id 8, estado **PRUEBAS** para cargar anuncios antes de abrirlo). Su tarjeta lleva a `/tianguis`. El encargado del negocio `tianguis` administra la sección; el dueño también. |
| `@Scheduled` diario | Sin scheduler; Render duerme sin tráfico | Se agrega `quarkus-scheduler` **y** los listados públicos filtran por `fechaVencimiento > ahora`, así un anuncio vencido no se ve aunque la tarea no haya corrido. |
| Límite por IP | `LimitePedidos` en memoria, IP de `X-Forwarded-For` | Mismo enfoque (`LimiteVentana` genérico). |
| Visibilidad | `Negocio.visiblePorSlug(slug, probador)` | API pública del tianguis respeta el estado del negocio `tianguis` (en pruebas solo probadores). |

Campos extra: `vendedor.bloqueado`, `anuncio.pausado_por` (VENDEDOR/ADMIN/REPORTES/BLOQUEO, para saber quién puede reanudar), `anuncio.renovaciones`, `anuncio.token_hash` (SHA-256), `anuncio.busqueda` (texto sin acentos para buscar igual en H2 y PostgreSQL), `anuncio.actualizado`.

## Pasos
1. Migración V34 (giro, negocio, 4 tablas, semilla de categorías con atributos). Entidades y reglas (atributos, transiciones, token).
2. API pública: categorías, listado con filtros/orden/paginación, detalle (+vistas). Admin: anuncios, estado, categorías, vendedores. Pruebas.
3. Fase 2 backend: publicar sin cuenta (honeypot, límites), fotos públicas, gestión por token (editar, vendido, pausar, renovar), reportes (3 → pausa), moderación (pendientes, rechazo con motivo, verificar, bloquear), vencimientos. Pruebas.
4. Frontend público: `/tianguis`, `/tianguis/c/:categoria`, ficha `/tianguis/:id-slug`, `/tianguis/publicar`, `/tianguis/reglas`, `/tianguis/mi-anuncio/:token`; SEO. Giro en el directorio.
5. Panel: sección Tianguis (anuncios, pendientes con contador, reportes, vendedores, categorías), formulario con atributos dinámicos y fotos.
6. Revisión visual, CI, PR con resumen.
